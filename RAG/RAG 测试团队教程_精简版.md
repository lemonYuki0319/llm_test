# RAG 测试团队教程

> 面向 AI 测试团队的 RAG（检索增强生成）测试速查手册。版本 v1.0 | 2026-06-29

---

## 一、定义

**RAG 测试**：在"检索 + 生成"两段式架构下，验证系统**检索得准、生成得实**——即检索环节召回正确知识,生成环节忠实于知识库、不编造、答得全。

核心差异：

| 维度 | Prompt 测试 | RAG 测试 |
|------|-------------|----------|
| 被测对象 | 单一模型输出 | 检索 + 生成 **两段链路** |
| 核心风险 | 指令不遵循、跑题 | **幻觉**（答案脱离知识库）、**检索漏召** |
| 评估依据 | 参考答案 + 评分卡 | **知识库内容（context）** 作为事实基准 |
| 失败归因 | Prompt 问题 | 要**区分**：检索错了 or 生成错了 |

---

## 二、RAG 链路与测试切点

```
用户问题 Query
    ↓
① 检索 Retrieval → ② 召回内容 Retrieved Context
    ↓                      ↓
③ 生成 Generation → ④ 最终答案 Answer
    ↓                      ↓
测检索质量            测生成质量
Context Precision     Faithfulness
Context Recall        Answer Relevancy
```

| 切点 | 测什么 | 核心问题 |
|------|--------|----------|
| **知识库层** | 切片粒度、Embedding质量 | 知识本身是否可被检索到 |
| **检索层** | 召回是否准、是否全 | 该召回的召回了吗？噪声多吗？ |
| **生成层** | 是否忠实context、是否编造 | 答案是不是真来自知识库？ |
| **端到端** | 整体答案质量 | 用户拿到的答案对不对 |

## 三、核心资产

| 资产 | 主责人 | 来源与要求 |
|------|--------|-----------|
| **知识库快照** | 算法工程师 | **必须版本化**（KB tag），测试集与之绑定 |
| **测试集（QA对）** | 测试人员主导 | 见下方配比，每条含 question + 标注 context |
| **参考答案（ground_truth）** | 业务专家 + 测试 | 从知识库提炼，用于算 Recall/Correctness |

### 测试集来源配比

| 来源 | 占比 | 说明 |
|------|------|------|
| 真实用户提问日志 | 40-50% | 脱敏后按知识域分类 |
| 业务专家基于知识库构造 | 20-30% | 覆盖知识盲区、易混淆点 |
| 测试设计的对抗/边界 | 20-30% | 知识库外问题、多跳问题、噪声问题 |
| 线上 Bad Case | 持续补充 | 幻觉/漏答 case 每周汇总 |

### ⚠️ RAG 特有测试集类型（必须覆盖）

```
✅ 可答问题        → 知识库里有答案，考检索+生成
✅ 知识库外问题    → 知识库里没有，考"拒答/不编造"（防幻觉关键）
✅ 多跳问题        → 答案需综合多个片段，考检索完整性
✅ 噪声/干扰问题   → 存在相似但错误的片段，考排序与忠实度
```

## 四、核心评估指标

> 全部 0~1 分，越高越好。分为**检索侧**和**生成侧**两组。

### 检索侧指标

| 指标 | 中文 | 定义 | 需要什么 |
|------|------|------|----------|
| **Context Precision** | 上下文精确率 | 召回的context中，相关的排得够靠前吗 | question + context + 参考 |
| **Context Recall** | 上下文召回率 | 参考答案的每个要点，都能在召回context中找到吗 | question + context + **ground_truth** |

📌 **归因**：Context Recall低 → 该召回的没召回（检索漏了）；Context Precision低 → 召回了太多噪声。

### 生成侧指标

| 指标 | 中文 | 定义 | 需要什么 |
|------|------|------|----------|
| **Faithfulness** | 忠实度 | 答案里的每个断言，都能被context支撑吗（防幻觉核心） | context + answer |
| **Answer Relevancy** | 答案相关性 | 答案是否紧扣问题、不跑题不啰嗦 | question + answer |

📌 **归因**：Faithfulness低 = **幻觉**（答案编造，脱离context）；Answer Relevancy低 = 跑题。

### 指标归因决策表（核心）

```
检索准(Recall高) + 生成实(Faithfulness高)  → ✅ 系统正常
检索差(Recall低) + 生成实(Faithfulness高)  → ⚠️ 检索问题：改切片/Embedding
检索准(Recall高) + 生成虚(Faithfulness低)  → ⚠️ 生成问题：改Prompt/换模型
检索差 + 生成虚                             → ❌ 双故障，先修检索再修生成
```

## 五、三层评估体系

```
Layer 1: 自动指标（成本 ≈ 0）
  ├─ 检索命中率（召回片段ID是否包含标注的相关ID）
  ├─ 答案格式/引用校验
  └─ 拒答规则（知识库外问题是否正确拒答）

Layer 2: RAGAS + LLM-as-Judge（几分钱/条）★核心
  ├─ RAGAS跑：Context Precision/Recall、Faithfulness、Answer Relevancy
  ├─ Judge模型 ≥ 被测生成模型
  └─ 结合知识库context对每条输出打分 + 归因

Layer 3: 人工复核（成本最高，只查关键case）
  ├─ 低分case（任一指标 < 阈值）→ 必查
  ├─ 幻觉嫌疑case（Faithfulness低）→ 必查
  └─ 知识库外问题误答 → 必查
```

### 评估方式配比

| 测试阶段 | 自动指标 | RAGAS/LLM | 人工复核 |
|----------|----------|-----------|----------|
| 冒烟/回归 | 100% | 0% | 0% |
| 常规评估 | 20% | 60% | 20% 抽样 |
| 上线验收 | 15% | 35% | 50% |

### RAGAS/LLM-as-Judge 关键规则

- **Judge模型 ≥ 被测生成模型能力**
- **每月抽样100条**，RAGAS打分 vs 人工打分校准，**一致性 < 85% 需重新设计**
- 知识库更新后，**评测集必须同步更新并重跑基线**

## 六、五阶段流程

```
Phase 1: 准备
  ① 拿需求+确定知识域 → ② 锁定知识库快照(KB tag)
  → ③ 构建QA测试集 → ④ 各指标阈值对齐

Phase 2: 执行
  ⑤ 批量调用RAG接口，采集(question, retrieved_context, answer)
  （每个用例跑3次检测检索/生成随机性）

Phase 3: 三层评估
  ⑥ 自动指标 → ⑦ RAGAS批量打分 → ⑧ 人工复核(低分/幻觉)

Phase 4: 输出
  ⑨ 检索vs生成归因 → ⑩ 产出报告 → ⑪ 优化 → 回归

Phase 5: 持续运营
  ⑫ 收集线上Bad Case → ⑬ 每周回归 → ⑭ 每月校准
```

## 七、性能指标（RAG必做项）

| 指标 | 阈值 | 说明 |
|------|------|------|
| 检索延迟 | < 500ms | 向量召回 + 重排耗时 |
| 首 token 延迟 TTFT | < 2s | RAG比纯生成更长，放宽 |
| 总响应时间 | < 12s | 含检索 + 生成 |
| 并发能力 | 按业务 QPS | 向量库压测 |

## 九、Top 5 易踩的坑

| 坑 | 后果 | 解决 |
|------|------|------|
| 评测集不标注context/ground_truth | Recall算不了 | 每条必须标注相关片段ID + 参考答案 |
| 知识库版本不锁定 | 指标不可复现 | 知识库打tag，评测集与之绑定 |
| 只测"可答"不测"库外" | 幻觉上线爆雷 | 库外拒答用例 ≥ 20% |
| 混淆检索错和生成错 | 优化打错方向 | 用归因决策表分段定位 |
| 知识库更新不重跑基线 | 指标漂移不自知 | 每月知识库同步 + 重跑基线 |

---

## 十、上线前检查清单

```
□ 知识库快照已锁定（KB tag），与评测集绑定
□ 评测集 ≥ 100 条，覆盖 可答/库外/多跳/噪声
□ 每条用例已标注相关片段ID + ground_truth
□ 各指标阈值已和产品对齐
□ 每个用例跑3次，稳定性达标
□ 三层评估完成，低分case已人工复核
□ 库外问题拒答率达标
□ Faithfulness达幻觉红线（高危业务 ≥ 0.95）
□ 检索/生成延迟分段达标
□ RAGAS与人工校准一致性 ≥ 85%
```
