# 文档一：RAG 测试团队教程

> 面向 AI 测试团队的 RAG（检索增强生成）测试速查手册。

---

## 一、定义

**RAG 测试**：在"检索 + 生成"两段式架构下，验证系统**检索得准、生成得实**——即检索环节召回正确知识，生成环节忠实于知识库、不编造、答得全。

### 与 Prompt 测试的核心差异

| 维度 | Prompt 测试 | RAG 测试 |
|------|-------------|----------|
| 被测对象 | 单一模型输出 | 检索 + 生成 **两段链路** |
| 核心风险 | 指令不遵循、跑题 | **幻觉**（答案脱离知识库）、**检索漏召** |
| 评估依据 | 参考答案 + 评分卡 | **知识库内容（context）** 作为事实基准 |
| 失败归因 | Prompt 问题 | 要**区分**：检索错了 or 生成错了 |
| 关键资产 | 测试集 + Prompt | 测试集 + **知识库快照** + 标注 context |

> 💡 **一句话**：Prompt 测试问"答得好不好"，RAG 测试还要问"答案是不是**真的来自知识库**"。

---

## 二、RAG 链路与测试切点

**RAG链路流程**：
```
用户问题(Query) → ①检索(Retrieval:向量召回+重排) → ②召回内容(Retrieved Context)
→ ③生成(Generation: LLM+Prompt) → ④最终答案(Answer)

知识库(Knowledge Base) → 切片/Embedding → 检索
```

**测试切点**：
```
检索质量 → Context Precision / Context Recall
生成质量 → Faithfulness / Answer Relevancy
```

| 切点 | 测什么 | 核心问题 |
|------|--------|----------|
| **知识库层** | 切片粒度、Embedding 质量、索引 | 知识本身是否可被检索到 |
| **检索层** | 召回是否准、是否全、排序对不对 | 该召回的召回了吗？噪声多吗？ |
| **生成层** | 是否忠实 context、是否答到点、是否编造 | 答案是不是真来自知识库？ |
| **端到端** | 整体答案质量 | 用户拿到的答案对不对 |

---

## 三、四类核心资产

| 资产 | 主责人 | 来源与要求 |
|------|--------|-----------|
| **知识库快照** | 算法/数据工程师 | **必须版本化**（KB tag），测试集与之绑定 |
| **测试集（QA 对）** | 测试人员主导 | 见下方配比，每条含 question + 标注 context |
| **参考答案（ground_truth）** | 业务专家 + 测试 | 从知识库中提炼，用于算 Recall/Correctness |
| **评估标准（阈值）** | 测试 + 产品对齐 | 各指标及格线，量化可操作 |

### 测试集来源配比（对齐 Prompt 教程）

| 来源 | 占比 | 说明 |
|------|------|------|
| 真实用户提问日志 | 40-50% | 脱敏后按知识域分类 |
| 业务专家基于知识库构造 | 20-30% | 覆盖知识盲区、易混淆点 |
| 测试设计的对抗/边界 | 20-30% | 知识库外问题、多跳问题、噪声问题 |
| 模型反向生成 | 10% | 从知识片段反推问题，需人工过滤 |
| 线上 Bad Case | 持续补充 | 幻觉/漏答 case 每周汇总 |

### ⚠️ RAG 特有的测试集类型（必须覆盖）

```
✅ 可答问题        → 知识库里有答案，考检索+生成
✅ 知识库外问题    → 知识库里没有，考"拒答/不编造"（防幻觉关键）
✅ 多跳问题        → 答案需综合多个片段，考检索完整性
✅ 噪声/干扰问题   → 存在相似但错误的片段，考排序与忠实度
✅ 时效性问题      → 知识库已更新，考是否用旧知识
```

## 四、核心评估指标（RAG 专属）

> 全部 0~1 分，越高越好。分为**检索侧**和**生成侧**两组。

### 4.1 检索侧指标（评"检索得准不准"）

| 指标 | 中文 | 定义 | 需要什么 |
|------|------|------|----------|
| **Context Precision** | 上下文精确率 | 召回的 context 中，相关的排得够靠前吗（precision@k 加权） | question + context + 参考 |
| **Context Recall** | 上下文召回率 | 参考答案的每个要点，都能在召回 context 中找到吗 | question + context + **ground_truth** |

> 📌 **归因**：Context Recall 低 → 该召回的没召回（检索漏了）；Context Precision 低 → 召回了太多噪声（排序/过滤差）。

### 4.2 生成侧指标（评"答得实不实"）

| 指标 | 中文 | 定义 | 需要什么 |
|------|------|------|----------|
| **Faithfulness** | 忠实度 | 答案里的每个断言，都能被 context 支撑吗（防幻觉核心） | context + answer |
| **Answer Relevancy** | 答案相关性 | 答案是否紧扣问题、不跑题不啰嗦 | question + answer |
| **Factual Correctness** | 事实正确性 | 答案与参考答案的事实一致度 | answer + **ground_truth** |

> 📌 **归因**：Faithfulness 低 = **幻觉**（答案编造，脱离 context）；Answer Relevancy 低 = 跑题/答非所问。

### 4.3 指标归因决策表（核心）

```
检索准(Recall高) + 生成实(Faithfulness高)  → ✅ 系统正常
检索差(Recall低) + 生成实(Faithfulness高)  → ⚠️ 检索问题：改切片/Embedding/重排
检索准(Recall高) + 生成虚(Faithfulness低)  → ⚠️ 生成问题：改Prompt/换生成模型
检索差 + 生成虚                             → ❌ 双故障，先修检索再修生成
```

**RAG评测低分归因流程**：
```
1. 检查Context Recall
   低 → 检索侧问题（切片/Embedding/重排/TopK）
   高 → 继续检查

2. 检查Faithfulness
   低 → 生成侧幻觉（改Prompt/换模型/加约束）
   高 → 继续检查

3. 检查Answer Relevancy
   低 → 跑题（Prompt引导不足）
   高 → ✅大概率通过
```

## 五、三层评估体系（对齐 Prompt 教程）

```
Layer 1: 自动指标（成本 ≈ 0）
  ├─ 检索命中率（召回片段ID是否包含标注的相关ID）
  ├─ 答案格式/引用校验（是否带来源、是否JSON）
  └─ 拒答规则（知识库外问题是否正确拒答）

Layer 2: RAGAS + LLM-as-Judge（几分钱/条）★核心
  ├─ RAGAS跑：Context Precision/Recall、Faithfulness、Answer Relevancy
  ├─ Judge模型 ≥ 被测生成模型
  └─ 结合知识库context对每条输出打分 + 归因

Layer 3: 人工复核（成本最高，只查关键/有异议）
  ├─ 低分case（任一指标 < 阈值）→ 必查
  ├─ 幻觉嫌疑case（Faithfulness低）→ 必查
  ├─ RAGAS与人工判断冲突 → 业务专家仲裁
  └─ 知识库外问题误答 → 必查
```

### 评估方式配比

| 测试阶段 | 自动指标 | RAGAS/LLM | 人工复核 |
|----------|----------|-----------|----------|
| 冒烟/回归 | 100% | 0% | 0% |
| 常规评估 | 20% | 60% | 20% 抽样 |
| 上线验收 | 15% | 35% | 50% |

### RAGAS/LLM-as-Judge 关键规则（对齐 Prompt 教程铁律）

- **Judge/评估模型 ≥ 被测生成模型能力**
- **每月抽样 100 条**，RAGAS 打分 vs 人工打分校准，**一致性 < 85% 需重新设计指标 Prompt / 阈值**
- 知识库更新后，**评测集必须同步更新并重跑基线**

## 六、五阶段流程

```
Phase 1: 准备
  ① 拿需求+确定知识域 → ② 锁定知识库快照(KB tag)
  → ③ 构建QA测试集(标注context+ground_truth) → ④ 各指标阈值对齐
                ↓
Phase 2: 执行
  ⑤ 批量调用RAG接口，采集(question, retrieved_context, answer)
  （每个用例跑3次检测检索/生成随机性）
                ↓
Phase 3: 三层评估
  ⑥ 自动指标(命中率/拒答) → ⑦ RAGAS批量打分 → ⑧ 人工复核(低分/幻觉/冲突)
                ↓
Phase 4: 输出
  ⑨ 检索vs生成归因 → ⑩ 产出报告 → ⑪ 优化(切片/Embedding/Prompt) → 回归
                ↓
Phase 5: 持续运营
  ⑫ 收集线上幻觉/漏答Bad Case → ⑬ 每周回归 → ⑭ 每月校准指标+知识库同步
```

### RAG 失败归因分类

```
检索漏召（Retrieval Miss）  → 该召回的知识没召回（Context Recall低）
检索噪声（Retrieval Noise） → 召回一堆无关片段（Context Precision低）
幻觉（Hallucination）       → 答案脱离context，编造事实（Faithfulness低）
跑题（Off-topic）           → 答非所问（Answer Relevancy低）
该拒未拒（Over-answer）     → 知识库外问题却硬答
不完整（Incomplete）        → 多跳问题只答了一部分
知识库问题（KB Issue）      → 切片断裂/知识本身缺失或过期
```

## 七、安全 + 性能（RAG 必做项）

### RAG 特有安全测试

**检索侧**：越权检索（能否检索到无权限文档）、知识库注入（恶意文档污染）、跨租户数据泄露

**生成侧**：幻觉编造（法律/医疗/金融等高危领域）、引用伪造（编造不存在的来源）、敏感信息泄露（把内部文档原文吐出）

**RAG 安全数据集起步**：知识库外诱导 20 + 越权检索 15 + 幻觉诱导 20 + 引用核查 15 + 隐私泄露 15 + 注入污染 15 = 100 条

### 性能指标（RAG 链路更长，需分段）

| 指标 | 阈值 | 说明 |
|------|------|------|
| 检索延迟 | < 500ms | 向量召回 + 重排耗时 |
| 首 token 延迟 TTFT | < 2s | RAG 比纯生成更长，放宽 |
| 总响应时间 | < 12s | 含检索 + 生成 |
| 检索召回 TopK 耗时 | 按业务 | K 越大越慢，需权衡 |
| 并发能力 | 按业务 QPS | 向量库压测 |
| 单次成本 | 可控 | 检索 + 生成 + 评估 token |

## 十、评分与综合判定

### 10.1 指标阈值建议（按业务风险调整）

| 指标 | 一般业务 | 高危业务（医疗/金融/法律） |
|------|:---:|:---:|
| Context Precision | ≥ 0.7 | ≥ 0.8 |
| Context Recall | ≥ 0.7 | ≥ 0.85 |
| **Faithfulness** | **≥ 0.8** | **≥ 0.95**（防幻觉红线） |
| Answer Relevancy | ≥ 0.7 | ≥ 0.8 |

### 10.2 综合判定（对齐 Prompt 教程）

```
✅ 通过 = 全部满足：
 ① 每个核心指标 ≥ 对应阈值
 ② Faithfulness 达标（幻觉红线，高危业务一票否决）
 ③ 知识库外问题正确拒答
 ④ 无安全一票否决（越权/隐私/引用伪造）
 ⑤ 性能达标 + 稳定性达标

⚠️ 警告 = 非核心指标轻微低于阈值，但无幻觉、无安全问题
❌ 失败 = Faithfulness严重不达标(幻觉) / 该拒未拒 / 触发安全一票否决 / 多个核心指标不达标
```

## 十一、Top 5 易踩的坑（RAG 专属）

| 坑 | 后果 | 解决 |
|------|------|------|
| 评测集不标注 context/ground_truth | Recall/Correctness 算不了 | 每条必须标注相关片段ID + 参考答案 |
| 知识库版本不锁定 | 指标不可复现、无法回归 | 知识库打 tag，评测集与之绑定 |
| 只测"可答"不测"库外" | 幻觉上线爆雷 | 库外拒答用例 ≥ 20% |
| 混淆检索错和生成错 | 优化打错方向 | 用归因决策表分段定位 |
| 知识库更新不重跑基线 | 指标漂移不自知 | 每月知识库同步 + 重跑基线 |

## 十二、上线前检查清单

```
□ 知识库快照已锁定（KB tag），与评测集绑定
□ 评测集 ≥ 100 条，覆盖 可答/库外/多跳/噪声/安全 五类
□ 每条用例已标注相关片段ID + ground_truth
□ 各指标阈值已和产品对齐（区分一般/高危业务）
□ 每个用例跑 3 次，检索+生成稳定性达标
□ 三层评估完成，低分/幻觉 case 已人工复核
□ 库外问题拒答率达标，无越权检索
□ Faithfulness 达幻觉红线（高危业务 ≥ 0.95）
□ 检索/生成延迟分段达标
□ 失败已按 检索/生成 归因，优化方向明确
□ RAGAS 与人工校准一致性 ≥ 85%
□ 线上幻觉/漏答 Bad Case 收集机制已建立
```
